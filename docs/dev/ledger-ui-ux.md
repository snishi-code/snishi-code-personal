# simple-ledger — UI / UX

medical 側のコードは参照せず、snishi-code 系の抽象 UI 規約に従う。実装は
`apps/simple-ledger/src/ui/`、文言は `apps/simple-ledger/src/i18n/ja.ts`。

## 全体方針

- **表示順の正本は `domain/displayOrder` の 1 モジュールだけ**（v13.6 H1）。画面は独自の
  並び配列・並べ替え比較を持たない。3 つの並びを持つ:
  - **箱の並び**（`DISPLAY_BOX_KEYS`。自由に動かせるお金 → 自由に動かせないお金 → 投資 →
    月割り台帳 → カード・未払 → ローン → 収入 → 費用 → 純資産）。**ユーザー並び替え不可**の
    コード定数。勘定科目画面の 7 箱・タイムラインの 9 箱・内訳の枠（資産 4 / 負債 2）は
    すべてこの並びの部分集合（`orderedDisplayBoxes`）。
  - **科目の並び**（`compareAccountOrder` / `sortAccounts`）。role の優先順 → ユーザーが
    並び替えた順（`sortIndex`）→ 名前順。箱の並びとは別軸で、片方から他方を導出しない。
  - **6 分類の並び**（`DISPLAY_SECTION_KEYS` / `DISPLAY_SECTION_GROUPS`）。ホームのカードの
    段組み = 数値レンズの行 = グラフの系列順。**収支・純資産は「恒等式の行」**として
    式の後ろへ自動配置され（収支 = 支出の後 / 純資産 = 負債の後）、並べ替えの対象にしない。
  - どの箱に属するかの**分類**は、資産 4 グループだけ `domain/assetGroups`（`assetGroupOf`）が
    正本で、それ以外は `displayBoxIncludes`。**分類と並びを 2 か所で書き分けない**。
  - 並びは保存しない（wire / schema 非接触）。保存項目は従来どおり科目の `sortIndex` だけ。
- スプレッドシート風 UI にしない。操作入口を少なくする。
- 入力の主導線は **ホームの 収入 / 支出 / 振替 の 3 ボタンのみ**（ヘッダーに `+` は置かない）。
  補助操作はメニュー / 設定に集約。
- 白背景・控えめな線・teal を主色。角丸は控えめ（`--radius: 12px`）。
- タップ領域は **44px 以上**（`--tap: 44px`、`.icon-btn` / `.btn` / `.list__item` など）。
- **色だけに依存しない**: 状態はアイコン + 文言を併用（エラー=⚠+文、成功=✓+文、増減=記号 +/−）。
- **カードタップ = 編集**（全エンティティ共通・2026-08-15 作者合意）: 一覧の 1 件は
  **カード/行そのものを押すとその 1 件の編集シートが開く**。行に編集アイコンは置かない
  （仕訳・くり返し記帳のルール・持ち物 item・勘定科目で同じ）。カードに残る操作ボタン
  （終了 / 削除 / 終了 / 再開 / 補正）は押した操作だけを起こし、編集は開かない。
  タップ対象は中に操作ボタンを含むため `button` 要素にできず、`role="button"` + `tabIndex` +
  Enter / Space（正本 `src/ui/cardTap.ts`）。アクセシブル名は「編集: 名前」。
  押せない行（残高調整科目・開く先の無い導出仕訳行・並び替え中の科目行）はタップ対象にしない。
- 成功は toast。危険操作は明示確認。保存 / import / 削除は fail-closed。

## 画面構成（`src/ui/screens/`）

- **Dashboard**（初期表示・選択日断面の財務ダッシュボード）: H1 は視覚的に日付ラベル
  （アクセシブル名は「ホーム」）。上部に **収入 / 支出 / 振替** の 3 入力ボタン（唯一の入力起点）。
  表示日の切替は**ヘッダー中央の日付チップ（1 タップで OS カレンダー）**から（画面内にスイッチャーは置かない）。
  選択日までの収支（収入/支出/収支）と財政状態（資産/負債/純資産）。
  **各項目はそれぞれ専用の「内訳 + 推移」ページへ遷移する**（同じページに集約しない）:
  収入→`incomeBreakdown` / 支出→`expenseBreakdown` / 収支→`netIncome` /
  資産→`assetsBreakdown` / 負債→`liabilitiesBreakdown` / 純資産→`netAssets`。**フロー（収入/支出/収支）は
  `reportBasis` の期間合計、ストック（資産/負債/純資産）は同じ `reportBasis` の基準日**で出す。
  フローとストックの日付境界をずらさず、財政状態には日付を明示する。
  **「支出」= 通常支出 + 月割り**（補正による費用も通常支出に含める）。購入の仕訳（資産の取得）・
  返済・振替は支出に含めない。**支出はホーム独立セクションにしない**。**収支** = 収入 − 支出。
  ヘッダーから年・全期間へ直接切り替える旧 UI は置かない。年次の俯瞰は
  **タイムライン（時間平面）の数値レンズ**で行う（ヘッダーのズームが入口）。
  収支 + 財政状態の 6 枠は**額縁（`dashboard.frame`・sticky）として固定**し、下の仕訳だけが
  スクロールで流れる（実ユーズ④・2026-08-12）。
  下部に **期間内の仕訳**（保存される仕訳のみ・日付降順・50 件ずつ「さらに表示」で開く。
  計算で生まれる仕訳は混ぜない = 自分が付けた記録が埋もれない）と「すべて見る」
  （期間フィルタ付きで仕訳画面へ）。表示日は App の共有 state（`ReportPeriod`）で、
  ホーム / 各内訳ページ / 仕訳に伝播する。
- **内訳ページ（収入 / 資産 / 負債 / 純資産）= `Breakdown`（汎用・`section` で切替）**: ホームの各項目の
  タップ先。「その項目の科目内訳（行タップで仕訳へドリル）+ 推移グラフ」を見せる。会計概念は内部に残し、
  画面名・見せ方は個人家計向けに柔らかくする。**フロー（収入）はドリルに期間、ストック（資産/負債/純資産）は
  基準日を引き継ぐ**。純資産は元手の科目 + **今期の損益**（= retained earnings）+ 純資産の推移を出し合計は純資産。
  負債は **資金繰りへの導線**（`liabilitiesBreakdown.cashflowLink` → `cashflow`）を持つ
  （資金繰りは見る画面で、返済計画の登録・編集は月割り台帳の「支払用負債」）。
  負債の内訳は **カード・未払**（`payment-liability`）と **ローン**
  （`other-liability`）の 2 枠に分け、各枠の小計と全体合計を出す。空枠は出さない。
  推移は **単一正本** `breakdownData.buildSectionTrends`（ホーム・各内訳ページが同じ定義を使い数字をズラさない）。
  - **資産の内訳は 4 枠**: 預金など（自由に動かせる現預金 = `movable !== false` の daily-asset）→
    自由に動かせないやつ（`movable === false`）→ 投資 → **月割り台帳（1 行 = 残存価値の合計・
    タップで「月割り台帳」へ**。内訳は台帳画面で見る・`assetsBreakdown.ledgerRow`）。各枠に小計
    （`assetsBreakdown.subtotal.free` / `.fixed` / `.investment` / `.ledger`）+ 全体合計。投資を分けたければ
    科目を増やせば分かれる（専用機能は作らない）。枠**分け**の正本は `domain/assetGroups`
    （`assetGroupOf`）、枠の**並び**は `domain/displayOrder`（`ASSET_GROUP_KEYS` = 箱の並びの
    射影）で、**タイムラインの数値レンズの資産行の展開と共有**する。
- **ExpenseBreakdown（支出の内訳）**: ホーム「支出」のタップ先。通常支出 / 月割り /
  支出合計を期間に応じて表示し、支出の推移も出す。通常支出は同じ期間 + 通常支出フィルタ付きの
  Journal、月割りは「月割り台帳」（screen 名は歴史的に `allocations`）へ進める
  （CF へは飛ばさない）。
- **NetIncome（収支）**: ホーム「収支」のタップ先。収入 / 支出 / 収支の要約 + **月ごとの残り方
  （収支の推移）を主役**にする。科目別ドリルダウンはしない。
- **TimelineCalendar（タイムライン = 時間平面）**: ハンバーガーから開く確認専用画面
  （ヘッダーのズームを押した断面画面からもここへ着く）。横軸 = 時間、縦軸 = 勘定科目の箱。
  **ズーム（日/月/年）は持たない**（ヘッダーが正本・後述）。画面が持つのは
  **レンズ（見え方）**と窓の位置だけ。
  - **線分レンズ**（既定）: 存在期間の帯とフローのポッチ。ポッチのタップで
    ポップオーバー（フロー一覧 →「開く」で由来の実体へ）。「終了分も表示」で窓の外の線分も出す。
  - **数値レンズ**（v13.5 D で「年間・全体」画面を吸収したもの）: 行は**ホームの 6 カードと
    同じ 6 分類**（収入 / 支出 / 収支 / 資産 / 負債 / 純資産。ラベルも `dashboard.*` の同じ
    メッセージキー）。**月ズーム = 月列**（年をまたいで連続）/ **年ズーム = 年列**。
    現在・未来も各列末までの投影値を数値で表示し、BS も同じ列末時点。列見出しのタップは
    月 = その月末を基準日にしてホームへ / 年 = その年を月ズームで見る。
  - **段階的開示**（v13.5 E）: 子を持つ行は**行タップで開くインライン木**（ラベル列を字下げ・
    トグルは 44px・`aria-expanded`）。収入 → 収入カテゴリ / 支出 → 費用カテゴリ /
    **資産 → ホームの資産ドリルと同じ 4 グループ → 科目**（分類の正本は `domain/assetGroups`・
    並びは `domain/displayOrder`。内訳画面の 4 枠と共有）/ 負債 → 負債科目 /
    収支・純資産は葉（恒等式の行）。展開状態は画面ローカルで
    保存しない。旧構成の**費目の常時全展開と「月割り」の独立行は撤去**した（月割りは費用
    カテゴリに含まれ、残存価値は資産の「月割り台帳」グループ = 1 行として出る）。
    **負債行は BS と同じ集計**（総資産 − 純資産の引き算で作らない）で、C-2 の規約どおり
    子は自然符号の昇順（最も大きな負債が先頭・比較だけ符号つき）、数字は負債トークン色。
    子を持つ行の値は**列ごとに子の合計と一致**する（minor unit の整数のまま・途中で丸めない）。
  - **グラフレンズ**（v13.5 F）: **ストック 4 系列**の折れ線（資産 / 負債 / 純資産 /
    自由に動かせるお金）。値は**各バケット末断面のストック**で、線は階段（バケットの幅ぶん
    水平に引く）。**負債は debit-signed（負）**で描くので 0 の線をまたいで下へ伸びる。
    縦軸は表示中の系列だけで決め、0 は必ず含める。フローの棒・2 軸は持たない
    （科目単位の系列は次バッチ）。
    - **ラベル列 = 凡例トグル**: 系列名の行そのものがタップで表示 / 非表示（`aria-pressed`・
      44px・色見本チップ付き）。既定 ON は**純資産と自由に動かせるお金**。凡例は描画の正本で、
      OFF の系列は DOM にも出ない。凡例には窓の右端（最後のバケット末）の値を添える。
    - 色は `--series-<系列キー>` のカテゴリカルなトークン（会計区分の意味色と teal から引く。
      ハードコードしない）。**色だけに頼らない**ため系列ごとに線種を変え、凡例のチップも
      同じ線種で描く。SVG は `aria-hidden` なので、ON の系列の始点・終点は sr-only の本文で読める。
    - **日ズームでも描ける**（バケット = 日）。日の列を持たないのは数値レンズだけ。
    - 系列の算定は `domain/stockSeries` が**日付順の単一走査**で行う（列ごとに
      `deriveBalanceSheet` を回さない）。「自由に動かせるお金」の判定は `domain/cashflow` の
      `isFreeAsset` が単一正本（資金繰りの原資と同じ集合）。
  - **列も帯も「窓」で切る**: 全期間を常に描かず、可視範囲 + 前後バッファだけを DOM 化する。
    移動は横スクロールと前後ボタン（年送りボタンは持たない）。スクロール可能範囲は
    **データのある最初の年 〜 `CONTINUOUS_COST_HARD_CAP`(2100)**。旧「全体」の表示地平
    セレクタ（実績のみ / +30年 / 2100年まで）は、この範囲と横スクロールに溶けて**撤去**した。
  - 仕訳展開は `displayEntriesResultForAsOf` を**レンズごとに 1 回**だけ（線分は窓の右端、
    数値とグラフは最終列 / 最終バケットの末日まで）。数値レンズの集計は `periodMatrix` が日付順の単一走査で
    列バケットと列末残高を同時に作る。表・帯とも**その枠の中だけ**を横スクロールし、
    先頭の行ラベル列は固定する。
- **Journal**: 仕訳一覧。**保存される仕訳と計算で生まれる仕訳（持ち物の費用の行・
  ルール投影の購入の行）を同じ一覧に日付降順で混合表示**する（ソースは `reportEntriesForAsOf`。
  展開範囲 = いま表示している範囲・上限 `2100-12-31`）。検索（摘要・メモ）・期間・
  **勘定科目絞り込み**（各内訳ページからの遷移）。保存される仕訳は行タップで編集
  （購入の仕訳は借方 = 月割り台帳が読み取り専用・削除不可）、**計算で生まれた行のタップは
  「月割り台帳」へ遷移して元の項目 / ルールの編集シートを開く**。各行に **取消/返金**（逆仕訳）と
  削除。**ヘッダー期間（正本）に追従**して日付範囲が変わる。ただし**初回マウントでは追従しない**＝
  ドリルダウンで渡された日付範囲を上書きしない。日付・科目は画面内でも手動で上書きできる。
  **科目絞り込み中だけ、対象科目の自然な残高符号（資産・費用は借方、負債・純資産・収入は貸方）で
  金額を増加色 / 減少色にする**。金額の符号は変えず、アクセシブル名にも「残高が増える / 減る」を
  含めて色だけに依存しない。export には計算で生まれる仕訳を混ぜない。
  検索・期間・並び替え・件数は**額縁（`journal.filterFrame`・sticky）として固定**し、
  仕訳カードだけがその下を流れる（ホームの額縁と同型・2026-08-15）。画面タイトルは含めない。
  額縁が画面の大半を占める低背ビューポート（高さ 640px 以下 = 横向き実機など）では固定を外す。
- **Entry**（シート）: 入力モード（収入/支出/振替/詳細）。日常入力は**お金の流れ `源泉 → 行き先`**で
  見せ、**借方/貸方や資産/負債/収益/費用の分類見出しは出さない**。並びは人間の入力順
  （**日付 → 項目 → 金額 → お金の流れ（A → B）→ 詳細**）。内部対応は常に source=貸方(credit) /
  destination=借方(debit): 収入 `収入元 → 入る場所`、支出 `支払い方法 → 使い道`（現金/預金/カードを
  並列に flat 表示）、振替 `移動元 → 移動先`（項目は任意・未入力なら「移動元 → 移動先」を自動付与）。
  候補は科目の **`role`** で絞る。`FlowPicker`（`AccountPicker` の flat モード + 矢印 `→`）を使う。
  メモは「詳細」折りたたみに収める。
  科目は**チップピッカー**（`AccountPicker`、単一選択 radio）。「詳細入力」で借方/貸方直接指定
  （manual。月割り台帳は候補に出ない）へ切替可。取消/返金は逆仕訳をプリセット。日付の既定は
  今日（必須）。支出では**お金の流れの行き先に「持ち物として持つ」ボタン**を置き、タップで
  行き先が**項目名の自由入力欄**に変わる（`data-ui=journal.entry.ccToggle` / `ccName`）。入力順は
  **項目名 → 終了日（`ccEndDate`・任意。空なら費用の割り振りをしない）→ 費用の行き先（`ccCategory`）**。
  項目名は**勘定科目ではなく持ち物の名前**（`MonthlyCostItem.name`・勘定科目は増えない）。
  保存は「借方だけを月割り台帳に差し替えた普通の仕訳保存 + item 作成」（`createContinuousCost`。
  購入の仕訳は保存される）。開始日 = 仕訳の日付・支払い元 = ユーザーが選んだ貸方がそのまま使われる。
  **持ち物としての登録は支出と簿記編集（manual）の新規作成で常に選べ、支払い元の役割では絞らない**
  （保存境界 = 内部集約・残高調整以外の全科目 `RECURRING_POSTABLE_ROLES` + 初期残高。
  ローンで買う・給与から直接引く形も簿記編集で登録できる）。通常支出でローンを
  支払い元にはできない（`entry.error.loanNotExpense`）。支払い元が負債（カード/ローン）
  のときだけ「分割/後日引落を資金繰りに入れる」を出し、引落口座・返済回数・初回引落日を入力できる
  （返済 = 未来日付の保存される仕訳 N 本。費用ではない）。
  - **支払い元の導線（チェックボックス廃止・持ち物としての登録と同じ片側切替に統一）**: 既定は現金・預金・
    クレジットカード。**ローンは支払い元（左辺）の「ローンを組む」ボタン**（`loanArrange`）で、押すと左辺が
    **既存ローン選択 + 新規ローン作成（`liabilityCreate`＝同じ導線内）**へ切り替わる。**クレジットカードは支払い
    方法として既定で出す**ためローン導線とは混ぜない（カード新規作成は勘定科目管理）。通常支出でローンを
    支払い元にはできない（持ち物としての登録＝資産取得のみ）。
- **月割り台帳**（`Allocations.tsx`。screen 名は歴史的に `allocations`）: 3 セクション構成。
  上段 = **くり返し**（定期ルール一覧: 名前・周期（「{n}か月ごと {day}日」）・源泉・金額・月あたり）、
  中段 = **持ち物**（項目名・期間（開始日〜終了日。未設定は `—`。費用化の開始日を
  設定した項目だけ「費用化 {日付}〜」を追加表示）・残存価値・月あたり）、
  下段 = **支払用負債**（v13.4 ④ で資金繰りから移設。カード・ローンの返済予定の登録・編集）。
  上段が「金が動く予定」、中段が「その解釈の残高」。同じ名前が両方に出るのは正しい。
  **一覧表示はヘッダーの選択日 D に追従**する。ルールの実効開始日 / item の開始日が D より後なら
  出さず、ルールは exclusive な終了日以降、item は終了日を過ぎた断面で終了済みとする。
  終了判定・終了間近・「今月」は D 時点で計算する。回収額は常に現在わかっている全実仕訳から計算し、
  後日の回収も過去へ遡及して残存価値を再配分する。現在は終了済みでも D 当時有効だった項目は表示する。
  一方、各シートの書込既定日は実際の今日のままにする（起票機構は存在しない・v13）。
  「終了分も表示」・検索・並び替えは**額縁（`allocations.filterFrame`・sticky）として固定**し、
  ルール一覧と item カード・負債行だけがその下を流れる（Journal と同型・2026-08-15）。額縁は 113px と
  低いので、低背ビューポートでも固定を外さない（仕訳一覧の 640px 境界は共有しない）。
  検索は 3 セクションすべてに効き（負債は科目名で当たる）、額縁の出現条件にも負債行を数える。
  並び替えの軸はルールと item だけに効く（負債は勘定科目順のまま）。
  - **追加は 2 択チューザー**（`allocations.add.chooser`）: くり返し記帳（`RecurringRuleSheet`）/
    いま持っているものを登録（持ち物シート。登録＝編集の 1 コンポーネント）。
    支払用負債は「追加」の対象ではない（科目そのものは勘定科目管理で作る）。
  - **ルールシート**: 独自の種別は置かず、貸方（支払い元・減る側）→借方（増える・使う側）と
    周期（か月・`recurring.every`）を登録する。両辺は通常の全会計区分から選べる。すべての
    費用行きルールは自動で持ち物 item を経由し、費用以外は直接起票する。利用者が月割りを
    切り替えるチェックは置かない。ルールの開始日は存在期間の開始（含む）で、周期の位相を持つ
    `startMonth` や item の起票日とは別に扱う。終了日は含まない端点で、終了した
    segment も過去のルールとして保持する。「終了」は**終了日シート**（`allocations.recurring.endSheet`）
    で終了点を打ち（既定 = 今日で置ける最小の排他的終了点 = 起票済み事実の翌日と今日の遅い方）、
    「同じ設定で新しく始める」は**確認ダイアログ**の後に今日開始の独立した線分を作る。どちらも
    無確認では実行しない。終了分は一覧の表示切替から再確認できる。
  - **金額変更の選択**: 既存ルールの金額を変えて保存すると、確認シートで
    「過去から変更」/「今日から新しい金額」を必ず選ぶ。「過去から変更」は、そのルールが自動生成した
    全仕訳・item（手編集済みの月を含む）を新額へ揃える。「今日から」は今日で旧 segment を閉じ、
    同日開始の後継 segment を作る。今日以降に起票済みのものは後継へ移し、過去分は変えない。
    移管済みの実績は金額と由来だけを変え、個別編集済みの摘要・科目・item の名称・期間・月割り先を
    保持する。金額以外のルール設定変更は次の未起票回から反映する。
    旧 segment が今日より前に存在し、今日も期間内にある場合だけ「今日から」を表示する。開始前・
    開始当日・終了後は「過去から変更」だけを表示する。確認をキャンセルした場合は何も保存しない。
  - **起票日との境界**: `4/12` 開始・毎月 `20日` のルールを `4/18` に「今日から」で変更すると、
    旧 segment は item を作らず `4/20` は新 segment が作る。`4/22` に変更すると `4/20` は旧 segment
    に残り、新 segment は翌月から作る。存在期間の端点と起票日の前後関係をこの規則で統一する。
  - **ルールから生まれたものは読み取り専用**（2026-08-15 作者決定）: ルールは定期起票するだけの
    軽い道具で、起票された仕訳（`rec-`）と item（`ccr-`）には行アクション（編集・削除・終了・
    反対仕訳）を**一切出さない**。タップは由来ルールの編集シートへ行く（`entryOpenPlan` が単一
    正本）。**未起票の導出カードと保存済みカードは見た目も操作も完全に同型**になる。調整は
    ルール側の編集・終了・再開だけで行う。「この回をスキップ」は概念ごと撤去した。
  - **削除はカスケード**: ルール本体と、そのルールから生まれた仕訳・持ち物をまとめて消す
    （積み木モデル: 下が消えれば上も消える。個別操作を持たない以上、起票だけ残すと誰も触れない
    孤児になる）。確認では**一緒に消える起票回数**と「同じ内容で登録し直せば復旧できる」ことを
    示す（起票ゼロなら「まだ起票はありません」）。利用者自身が切った反対仕訳は残り、由来リンク
    だけが外れる。削除・金額変更・segment 分割はいずれも保存完了まで画面状態を先へ進めず、
    失敗時は全体を中断して通知する。
  - **持ち物シート**: 項目名 / 金額（購入額）/ 開始日（編集時は読み取り専用・タップで
    購入の仕訳へ）/ 費用化の開始日（任意・既定 = 購入日。購入日より後にすると、その間は台帳に
    価値が置かれたまま）/ 終了日（空でよい + クイックチップ [1年][3年][5年] = 月末方式。起点は
    費用化の開始日）/ 計上先。
  - **並びは終了が近い順**（終了日なしは最後）。**終了まで 1 ヶ月以内は行の背景色を少し変える**
    （`data-ending`）。バッジ・状態ラベルは置かない。
  - **終了 = 終了日の設定**（行アクション `allocations.archive` → 小ダイアログで終了日・
    残存価値を表示）。残存価値 > 0 なら「振替先を選ぶ」でホームの振替と同じシートを開き、
    回収の振替を保存する。終了日を過ぎた項目は一覧から消え、「終了分も表示」で全件出す。
    終了済みの行の同じボタンで終了日を先へ動かせば一覧に戻る（復元も同じ 1 操作）。
  - **過去から再計算の明示**: 編集シートで金額・期間・費用の行き先を変えると「過去から再計算
    されます」の注意を出す（`data-ui=allocations.edit.impactWarning`）。費用の行は保存されない
    導出なので過去集計が変わる＝仕様（[過去編集モデル](ledger-concept.md#過去編集モデルあとから意味を組み替える)）。
  - **支払用負債**（`allocations.liability.list`。v13.4 ④ で資金繰りから移設・作者確定 2026-08-17）:
    **返済予定の登録・編集はこの台帳が持つ**（資金繰りは見るだけ）。行 = カード・ローン
    （`payment/other-liability`）のうち**基準日断面で導出残高 ≠ 0** のものだけで、資金繰りと
    同じ単一正本（`domain/cashflow.ts` の `liabilityScheduleRows`）から作る。行の形は
    ルール行と同じ設計図（左 = 名前・返済設定・次回支払日/残回数/残額 / 右列 = 上段 残高・
    下段 動詞）。動詞は tonal ボタン **「返済を登録」**（`allocations.repay.add`）で、
    返済シート（`RepaymentScheduleSheet.tsx`・`allocations.repay.sheet`）を開く。
    行そのものはタップ対象にしない（この行の「編集」＝返済予定の登録そのもので、
    それが下段のボタン）。**行の展開**（`allocations.repayments.toggle`）で登録済みの返済
    （基準日より後の保存される仕訳・借方 = その負債）が並び、タップでそのまま仕訳の編集シートを
    開く（`allocations.repayments.row`）。
    返済シートの日付**既定値**だけが today 規約 (a) の例外（表示の断面は period のまま）。
  - **資金繰りからの着地**（`AllocationsTarget.liabilityAccountId`）: 資金繰りの負債行タップは
    itemId / ruleId と同型の target で台帳へ渡る。ただし item / rule と違って**シートは開かず**、
    該当行へスクロールして登録済みの返済を展開する（見に来た人の目的地は行そのもの）。
    その断面に行が無い（完済済みなど）ときは何も起きない。
- **Accounts**（`Accounts.tsx`・単独画面のほか「補正・勘定科目」内に `embedded` で統合）: 勘定科目を区分ごとに
  残高つきで管理。追加 / 編集 / 終了 / 削除（参照中は不可）。**編集は行そのもののタップ**
  （残高調整科目の行と並び替え中は押せない）。所属する箱（`type` / `role`）は固定し、
  編集シートで名前・開始日・終了日を変更できる。**内部・聖域化の役割
  （月割り台帳=`continuing-cost-asset`）はユーザー編集対象でないため一覧・
  ロール選択肢に出さない**（`isInternalRole`。BS / 資産の内訳には残高として現れる）。存在期間は
  仕訳・持ち物・定期ルールの参照期間を包含しなければならない。embedded 時は各 BS
  科目行に**「補正」ボタン**（`accounts.adjust`）を出す。
  - 一覧はヘッダーの断面日で存在する科目だけを通常表示し、「終了分も表示」で断面外の科目も確認できる。
    仕訳入力の科目候補はヘッダーではなく、フォームで選んだ仕訳日を基準に絞る。
  - **「自由に動かせる」チェック**（`accounts.movable`・現預金の内訳のみ・既定 ON）: OFF にすると
    資金繰りの原資「自由に動かせるお金」に数えない（Suica・チャージ残高など）。BS / 資産の内訳の
    表示は変わらない（「自由に動かせないやつ」枠に移るだけ）。保存されるのは OFF（`movable: false`）
    だけ（ON は保存境界で `undefined` へ正規化）。一覧では OFF の科目に「自由に動かせない」バッジを出す。
  - 箱見出しは細い左罫線で意味色を示す。資産=青系（自由/不自由は濃淡）・負債=赤系・収入=緑系・
    支出=黄〜オレンジ系・純資産=グレー。面を塗らず、`accountBoxes.ts` のアクセントを
    勘定科目・科目ピッカー・資産/負債内訳で共有する。
  - **終了 = 今日を `endDate` に記録**（`accounts.archiveToggle`）。残高が残る資産・負債の
    終了は**ホームの振替と同じシート**（EntrySheet の transfer 再利用・終了対象側は
    固定・金額既定 = |残高|）を経由し、振替の保存と `archived = true` を 1 トランザクションで行う。
    振替をキャンセルしたら終了もしない。費用・収入は累計が残っていても直接終了でき、
    分類を引き継ぎたい場合だけ同区分への 1 対 1 振替導線を任意で使う。過去日の表示では
    終了済み科目もその日の残高で出し続ける。終了の解除は `endDate` を消す。
    残高 0 の終了（`accounts.archiveConfirm`）と終了の解除（`accounts.unarchiveConfirm`）は
    確認ダイアログを通す（残高が残る経路は振替シート自体が確認を兼ねる）。
- **補正・勘定科目**（`Adjustments.tsx`、画面名 `manage.title`、**ハンバーガーメニューに昇格**）: 勘定科目管理 +

  - **勘定科目**（上部・`<Accounts embedded>`）: 一覧・追加・編集・終了/削除。各 BS 科目行の「補正」から

    月/年ズームでは窓の終端を**バケット末に揃える**（最後のバケットが半端に切れない）。

## ヘッダー（`src/App.tsx` 内）

**ヘッダーは時間だけに徹する**（ホーム = フッター中央 / 設定 = メニュー内が唯一の置き場所）。
時間には**いつ**（表示日）と**目盛り**（ズーム）の両方が含まれる。

- 中央 左: **表示日のチップ**（`UI.period.dateTrigger`）。チップに**透明な `<input type="date">` を
  重ねてあり、1 タップで OS のカレンダーが直接開く**（`UI.period.dateInput`。ポップアップの
  ピッカーは経由しない）。台帳名はヘッダーに出さない。
- 中央 中: **「今日」**（`UI.period.today`）。タイムスリップ中だけ現れるずれの警告灯。
  押すと**日付だけ**を今日へ戻す（画面もズームも動かさない）。
- 中央 右: **日 / 月 / 年**（`UI.period.zoom.*`）= 時間平面のズーム。

入力は **ホームの 3 ボタンに集約**し、ヘッダーに `+` は置かない。

### 表示日（1 タップ選択）

表示日は「DB からの抽出条件」＝**日付を 1 つ選んでその断面を見る**（既定 = 起動時の当日）。
`max = 2100-12-31`（`CONTINUOUS_COST_HARD_CAP`）を付け、エンジンが展開できる範囲の外を
そもそも選べなくする（仕訳一覧の from/to も同じ `max`。**入力欄の日付には付けない** —
過去の持ち込みも未来の終了日も自由に入れる）。ヘッダーを年・全期間へ切り替える
`PeriodYearPicker` 等は公開しない。年次の俯瞰は時間平面の数値レンズで行う。

表示日は `App` の共有 state（`ReportPeriod`）でホーム / 各内訳ページ / 仕訳に伝播する
（画面ごとに分岐しない）。

### ズーム 日 / 月 / 年（作者決定 2026-08-18・v13.5 D）

**時間平面の目盛り**。`App` の共有 state（`timeZoom`）が正本で、画面はローカルに持たない
（写真 App の 年別/月別/日別 と同型）。押しても**表示日は変えない**
（タイムスリップは日付チップだけの仕事。ズームは目盛りを変えるだけ）。

- **点灯 = ウィンドウ世界の名乗り**。時間の窓を描く画面（**タイムライン**・**資金繰り**。
  `ui/navigation.ts` の `supportsTimeZoom` が単一正本）に居るときだけ現在ズームが点灯する。
  ある 1 日を見る**断面画面ではすべて消灯**し、押すと**時間平面へ移動して**そこで点灯する
  （旧「年間・全体」ボタンの `openOverview` = 別画面なら移動・当画面なら切替、の一般化）。
- **タイムラインの数値レンズに日の列は無い**ので、**タイムラインに居るとき**レンズが数値なら
  「日」は `disabled`。理由はアクセシブル名（「日（数値では選べません）」）で名乗る。
  日ズームのまま数値レンズへ切り替えたら**月へ丸める**。
  **不変則はタイムラインでだけ効く**（v13.5 F）: レンズはタイムラインの見え方でしかないので、
  レンズを持たない**資金繰りでは日/月/年をすべて押せる**（D の段階では数値レンズのまま
  資金繰りへ行くと「日」が押せない取り違えがあった）。資金繰りで日を選んだままタイムライン
  （数値レンズ）へ戻る経路でも月へ丸める。強制点は `App` の `enforceLensZoom` 1 箇所で、
  `changeLens` / `changeZoom` / `go`（画面遷移）がそこを通る。
  **グラフレンズには日のバケットがある**ので丸めない。
- レンズ（線分/数値/グラフ）のセレクタは時間平面の画面内にあるが、**state は `App` が持つ**
  （上の「日」の可否がレンズに依存するため。旧 `overviewMode` が同じ理由でヘッダー側に居た）。
- **資金繰りもズームに追従する**（v13.5 F。D の時点では点灯対象なだけだった）。
  日 = 日繰り表（日次の点）/ 月 = 月次資金繰り表（月末断面 + 月次純増減の副表示）/
  年 = 年次計画（年末断面）。**投影も下回り日の探索も常に日次のまま**で、畳むのは
  グラフに描く点だけ（`domain/cashflow` の `foldCashflowPoints`）。

## メニュー（`src/ui/Menu.tsx`）

**中央モーダル / モバイルは下部シート**（共通 `Modal` の dialog variant。右ドロワー `.drawer` は廃止）。
背景タップ・Escape で閉じ、メニュー内クリックでは閉じない。独立した俯瞰画面と管理・補助機能を置く:
**タイムライン / 月割り台帳 / 資金繰り / 補正・勘定科目 / 設定 / ヘルプ**。ホーム=フッター中央、
仕訳=ホーム下部「期間内の仕訳」やドリルダウン、各内訳ページ=ホームの各項目から辿る（メニューには置かない）。
時間のズームは「場所」ではないのでメニュー項目を持たない（ヘッダーの 日/月/年 が入口）。
勘定科目・残高補正・初期残高は**「補正・勘定科目」に統合**（メニュー）。

## モーダル / シート規約（`src/ui/Modal.tsx`）

- 閉じ方は **`dismissMode`** で統一する（旧 `dismissable` は後方互換: `false`=`never` 相当）:
  - **`always`**: メニュー / ヘルプ / 軽い選択。背景タップ・`Escape` で閉じる（選んだら閉じる）。
  - **`if-clean`**: 入力フォーム。未編集なら閉じ、**編集済み（dirty）は破棄確認**を出す
    （`useDirtyGuard`。「入力を破棄しますか？」→ 破棄する / 編集を続ける。確認自体は `never`）。
    dirty 判定は各シートで入力フィールドのスナップショットを初期値と比較する。`×` / 背景タップ /
    `Escape` / フッターのキャンセルはすべて `requestClose` を通す。
  - **`never`**: 削除 / 全削除 / import / 復元など破壊的操作。背景タップ・`Escape` で**閉じない**。
- 背景タップ判定は **`onPointerDown` かつ `e.target === e.currentTarget`**（内部要素のタップでは閉じない）。
- 保存 / キャンセルがあるフォームは下部に明確なボタン。フォーカストラップ + 復帰、`role="dialog"` /
  `aria-modal`。

## 入力の保存規則（画面追加時の不変則・2026-08-15 作者合意）

- **端末ローカルの単一値の好み**（設定画面の表示桁数など `localFlags` /
  settings の 1 コントロール）は**即時反映**。保存ボタンを置かない（iOS 設定と同じ）。
  確定できる値だけを記憶する（入力途中の不正値は既定へ fail-soft）。
- **台帳データを作る / 変えるシート**（仕訳・ルール・持ち物 item・科目・補正）は
  **明示保存 + 破棄確認**（`dismissMode: 'if-clean'`）。即時保存にしない＝書きかけの記録を
  作らない。
- 検索・並び替え・表示期間などの**その場限りの表示状態**はどちらでもない（保存しない）。
  端末に記憶したくなったら「単一値の好み」として設定画面へ置く（画面内には置かない）。

## 状態を変える操作は必ず確認を挟む（2026-08-15 作者合意）

保存・終了・削除・スキップ・再開・終了など、データの状態を変える row-action は
無確認で即実行しない（「突然挙動するとユーザーが恐怖する」）。軽い確認（ConfirmDialog）か
専用シート（終了日・振替など入力が要るもの）のどちらかを必ず通す。
現在の確認面: 定期ルールの終了（終了日シート）/ 再開 / 削除（カスケードの注意文 + 起票回数）、
持ち物 item の終了（終了日シート）/ 削除、勘定科目の終了
（残高 0 = 確認ダイアログ / 残高あり = 振替シート）/ 解除。
ルール由来の仕訳・item はそもそも操作を持たない＝確認する対象も無い。

## toast（`src/ui/toast.tsx`）

- 成功 = success（teal）、失敗 = error（赤）。アイコン + 文言。`role="status"` / `aria-live="polite"`。
- **保存失敗時に成功 toast を出さない**（store の各アクションは失敗時 error toast + 例外送出）。

## 危険操作（`src/ui/ConfirmDialog.tsx`）

- 削除 / import 上書き / 復元は確認ダイアログ。確定ボタンは danger 色 + ⚠。
- 全データ削除は **キーワード入力一致**（「削除」と入力）まで確定を無効化。

## 復旧面（`src/ui/ErrorBoundary.tsx`）

ルート直下の ErrorBoundary が描画例外を受け、最小の復旧面を出す: 設定（JSON import への到達）と
**「DB を初期化して再起動」**（`app.recovery.wipe` = `deleteDatabase` → reload。VersionError で
起動できない詰みへの最終手段・確認ダイアログ付き）。「アプリ内の説明文を増やさない」ルールは
通常画面の話で、致命状態の復旧 UI は対象外。

## アクセシビリティ

- 主要操作は `getByRole` / `getByLabelText` で辿れるよう、ラベルと control を id で結ぶ。
- フォーム入力は 16px 以上（iOS のズーム回避）。
- コントラストは WCAG AA を満たす（teal-700 を白文字ボタン背景に使用）。
- スキップリンク、`:focus-visible` のフォーカスリング。
- E2E で axe-core の critical/serious 違反ゼロを検証（`e2e/a11y.spec.ts`）。
