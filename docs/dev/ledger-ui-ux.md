# simple-ledger — UI / UX

medical 側のコードは参照せず、snishi-code 系の抽象 UI 規約に従う。実装は
`apps/simple-ledger/src/ui/`、文言は `apps/simple-ledger/src/i18n/ja.ts`。

## 全体方針

- スプレッドシート風 UI にしない。操作入口を少なくする。
- 入力の主導線は **ホームの 収入 / 支出 / 振替 の 3 ボタンのみ**（ヘッダーに `+` は置かない）。
  補助操作はメニュー / 設定に集約。
- 白背景・控えめな線・teal を主色。角丸は控えめ（`--radius: 12px`）。
- タップ領域は **44px 以上**（`--tap: 44px`、`.icon-btn` / `.btn` / `.list__item` など）。
- **色だけに依存しない**: 状態はアイコン + 文言を併用（エラー=⚠+文、成功=✓+文、増減=記号 +/−）。
- 成功は toast。危険操作は明示確認。保存 / import / 削除は fail-closed。

## 画面構成（`src/ui/screens/`）

- **Dashboard**（初期表示・選択日断面の財務ダッシュボード）: H1 は視覚的に日付ラベル
  （アクセシブル名は「ホーム」）。上部に **収入 / 支出 / 振替** の 3 入力ボタン（唯一の入力起点）。
  表示日の切替は**ヘッダー中央の日付チップ（1 タップで OS カレンダー）**から（画面内にスイッチャーは置かない）。
  選択日までの収支（収入/支出/収支）と財政状態（資産/負債/純資産）。
  **各項目はそれぞれ専用の「内訳 + 推移」ページへ遷移する**（同じページに集約しない）:
  収入→`incomeBreakdown` / 支出→`expenseBreakdown` / 収支→`netIncome` /
  資産→`assetsBreakdown` / 負債→`liabilitiesBreakdown` / 純資産→`netAssets`。**フロー（収入/支出/収支）は
  `reportBasis` の期間合計、ストック（資産/負債/純資産）は同じ `reportBasis` の基準日**で出す。
  フローとストックの日付境界をずらさず、財政状態には日付を明示する。
  **「支出」= 通常支出 + 継続コスト**（補正による費用も通常支出に含める）。購入の仕訳（資産の取得）・
  返済・振替は支出に含めない。**支出はホーム独立セクションにしない**。**収支** = 収入 − 支出。
  ヘッダーから年・全期間へ直接切り替える旧 UI は置かない。年次の俯瞰は、ハンバーガー内の独立した
  **年間・全体**画面で行う。
  下部に **期間内の仕訳**（最大 5 件・日付降順、計算で生まれる仕訳も表示）と「すべて見る」
  （期間フィルタ付きで仕訳画面へ）。表示日は App の共有 state（`ReportPeriod`）で、
  ホーム / 各内訳ページ / 仕訳に伝播する。
- **内訳ページ（収入 / 資産 / 負債 / 純資産）= `Breakdown`（汎用・`section` で切替）**: ホームの各項目の
  タップ先。「その項目の科目内訳（行タップで仕訳へドリル）+ 推移グラフ」を見せる。会計概念は内部に残し、
  画面名・見せ方は個人家計向けに柔らかくする。**フロー（収入）はドリルに期間、ストック（資産/負債/純資産）は
  基準日を引き継ぐ**。純資産は元手の科目 + **今期の損益**（= retained earnings）+ 純資産の推移を出し合計は純資産。
  負債は **資金繰り・返済計画への導線**（`liabilitiesBreakdown.cashflowLink` → `cashflow`）を持つ。
  負債の内訳は **カード・未払**（`payment-liability`）と **ローン**
  （`other-liability`）の 2 枠に分け、各枠の小計と全体合計を出す。空枠は出さない。
  推移は **単一正本** `breakdownData.buildSectionTrends`（ホーム・各内訳ページが同じ定義を使い数字をズラさない）。
  - **資産の内訳は 4 枠**: 預金など（自由に動かせる現預金 = `movable !== false` の daily-asset）→
    自由に動かせないやつ（`movable === false`）→ 投資 → **継続コスト台帳（1 行 = 残存価値の合計・
    タップで「毎月のもの」へ**。内訳は台帳画面で見る・`assetsBreakdown.ledgerRow`）。各枠に小計
    （`assetsBreakdown.subtotal.free` / `.fixed` / `.investment` / `.ledger`）+ 全体合計。投資を分けたければ
    科目を増やせば分かれる（専用機能は作らない）。
- **ExpenseBreakdown（支出の内訳）**: ホーム「支出」のタップ先。通常支出 / 継続コスト /
  支出合計を期間に応じて表示し、支出の推移も出す。通常支出は同じ期間 + 通常支出フィルタ付きの
  Journal、継続コストは「毎月のもの」（screen 名は歴史的に `allocations`）へ進める
  （CF へは飛ばさない）。
- **NetIncome（収支）**: ホーム「収支」のタップ先。収入 / 支出 / 収支の要約 + **月ごとの残り方
  （収支の推移）を主役**にする。科目別ドリルダウンはしない。
- **YearlyOverview（年間・全体）**: ハンバーガーから開く確認専用画面。**年間**は選択した1年を
  1〜12月、**全体**はデータのある年を昇順で並べ、収入 / 支出 / 収支 / 継続コスト /
  費目別 / 総資産 / 純資産を表で表示する。年間の初期年はヘッダー選択日の年だが、画面内の年送りは
  ヘッダーを変更しない。未来列は 0 と区別して「—」。当月・当年は今日まで、BS は同じ基準日時点。
  表示範囲の仕訳展開は `reportEntriesForAsOf` 1回だけで、`periodMatrix` が日付順の単一走査で
  月別 / 年別バケットと期末残高を同時に作る。表だけを横スクロールし、先頭の行ラベルは固定する。
- **Journal**: 仕訳一覧。**保存される仕訳と計算で生まれる仕訳（継続コスト資産の費用の行・
  ルール投影の購入の行）を同じ一覧に日付降順で混合表示**する（ソースは `reportEntriesForAsOf`。
  展開範囲 = いま表示している範囲・上限 `2100-12-31`）。検索（摘要・メモ）・期間・
  **勘定科目絞り込み**（各内訳ページからの遷移）。保存される仕訳は行タップで編集
  （購入の仕訳は借方 = 継続コスト台帳が読み取り専用・削除不可）、**計算で生まれた行のタップは
  「毎月のもの」へ遷移して元の項目 / ルールの編集シートを開く**。各行に **取消/返金**（逆仕訳）と
  削除。**ヘッダー期間（正本）に追従**して日付範囲が変わる。ただし**初回マウントでは追従しない**＝
  ドリルダウンで渡された日付範囲を上書きしない。日付・科目は画面内でも手動で上書きできる。
  **科目絞り込み中だけ、対象科目の自然な残高符号（資産・費用は借方、負債・純資産・収入は貸方）で
  金額を増加色 / 減少色にする**。金額の符号は変えず、アクセシブル名にも「残高が増える / 減る」を
  含めて色だけに依存しない。export には計算で生まれる仕訳を混ぜない。
- **Entry**（シート）: 入力モード（収入/支出/振替/詳細）。日常入力は**お金の流れ `源泉 → 行き先`**で
  見せ、**借方/貸方や資産/負債/収益/費用の分類見出しは出さない**。並びは人間の入力順
  （**日付 → 項目 → 金額 → お金の流れ（A → B）→ 詳細**）。内部対応は常に source=貸方(credit) /
  destination=借方(debit): 収入 `収入元 → 入る場所`、支出 `支払い方法 → 使い道`（現金/預金/カードを
  並列に flat 表示）、振替 `移動元 → 移動先`（項目は任意・未入力なら「移動元 → 移動先」を自動付与）。
  候補は科目の **`role`** で絞る。`FlowPicker`（`AccountPicker` の flat モード + 矢印 `→`）を使う。
  メモ・タグは「詳細」折りたたみに収める。
  科目は**チップピッカー**（`AccountPicker`、単一選択 radio）。「詳細入力」で借方/貸方直接指定
  （manual。継続コスト台帳は候補に出ない）へ切替可。取消/返金は逆仕訳をプリセット。日付の既定は
  今日（必須）。支出では**お金の流れの行き先に「継続コスト資産として持つ」ボタン**を置き、タップで
  行き先が**項目名の自由入力欄**に変わる（`data-ui=journal.entry.ccToggle` / `ccName`）。入力順は
  **項目名 → 終了日（`ccEndDate`・任意。空なら費用の割り振りをしない）→ 費用の行き先（`ccCategory`）**。
  項目名は**勘定科目ではなく継続コスト資産の名前**（`MonthlyCostItem.name`・勘定科目は増えない）。
  保存は「借方だけを継続コスト台帳に差し替えた普通の仕訳保存 + item 作成」（`createContinuousCost`。
  購入の仕訳は保存される）。開始日 = 仕訳の日付・支払い元 = ユーザーが選んだ貸方がそのまま使われる。
  **継続コスト化は支出と簿記編集（manual）の新規作成で常に選べ、支払い元の役割では絞らない**
  （保存境界 = 内部集約・残高調整以外の全科目 `RECURRING_POSTABLE_ROLES` + 初期残高。
  ローンで買う・給与から直接引く形も簿記編集で登録できる）。通常支出でローンを
  支払い元にはできない（`entry.error.loanNotExpense`）。継続コスト ON ではタグ欄を隠す。支払い元が負債（カード/ローン）
  のときだけ「分割/後日引落を資金繰りに入れる」を出し、引落口座・返済回数・初回引落日を入力できる
  （返済 = 未来日付の保存される仕訳 N 本。費用ではない）。
  - **支払い元の導線（チェックボックス廃止・継続コスト化と同じ片側切替に統一）**: 既定は現金・預金・
    クレジットカード。**ローンは支払い元（左辺）の「ローンを組む」ボタン**（`loanArrange`）で、押すと左辺が
    **既存ローン選択 + 新規ローン作成（`liabilityCreate`＝同じ導線内）**へ切り替わる。**クレジットカードは支払い
    方法として既定で出す**ためローン導線とは混ぜない（カード新規作成は勘定科目管理）。通常支出でローンを
    支払い元にはできない（継続コスト化＝資産取得のみ）。
- **毎月のもの**（`Allocations.tsx`。screen 名は歴史的に `allocations`）: 2 セクション構成。
  上段 = **くり返し**（定期ルール一覧: 名前・周期（「{n}か月ごと {day}日」）・源泉・金額・月あたり）、
  下段 = **継続コスト資産**（項目名・期間（開始日〜終了日。未設定は `—`）・残存価値・月あたり）。
  上段が「金が動く予定」、下段が「その解釈の残高」。同じ名前が両方に出るのは正しい。
  **一覧表示はヘッダーの選択日 D に追従**する。開始月 / 開始日が D より後のルール・項目は出さず、
  終了判定・終了間近・「今月」は D 時点で計算する。回収額は常に現在わかっている全実仕訳から計算し、
  後日の回収も過去へ遡及して残存価値を再配分する。現在は終了済みでも D 当時有効だった項目は表示する。
  一方、catch-up や各シートの書込既定日は実際の今日のままにする。
  - **追加は 2 択チューザー**（`allocations.add.chooser`）: くり返し記帳（`RecurringRuleSheet`）/
    いま持っているものを登録（継続コスト資産シート。登録＝編集の 1 コンポーネント）。
  - **ルールシート**: 独自の種別は置かず、貸方（支払い元・減る側）→借方（増える・使う側）と
    周期（か月・`recurring.every`）を登録する。両辺は通常の全会計区分から選べる。すべての
    ルールに「継続コストとして扱う」チェック（`recurring.manualSpread`、既定 OFF）があり、
    ON のときだけ周期分を月割りする（費用の行き先 = 借方に選んだ科目）。停止/再開はルール側にだけ残る
    （再開時は位相を保ち、停止中の月を遡って起票しない）。
  - **継続コスト資産シート**: 項目名 / 金額（購入額）/ 開始日（編集時は読み取り専用・タップで
    購入の仕訳へ）/ 終了日（空でよい + クイックチップ [1年][3年][5年] = 月末方式）/ 費用の行き先。
  - **並びは終了が近い順**（終了日なしは最後）。**終了まで 1 ヶ月以内は行の背景色を少し変える**
    （`data-ending`）。バッジ・状態ラベルは置かない。
  - **アーカイブ = 終了日の設定**（行アクション `allocations.archive` → 小ダイアログで終了日・
    残存価値を表示）。残存価値 > 0 なら「振替先を選ぶ」でホームの振替と同じシートを開き、
    回収の振替を保存する。終了日を過ぎた項目は一覧から消え、「終了分も表示」で全件出す。
    終了済みの行の同じボタンで終了日を先へ動かせば一覧に戻る（復元も同じ 1 操作）。
  - **過去から再計算の明示**: 編集シートで金額・期間・費用の行き先を変えると「過去から再計算
    されます」の注意を出す（`data-ui=allocations.edit.impactWarning`）。費用の行は保存されない
    導出なので過去集計が変わる＝仕様（[過去編集モデル](ledger-concept.md#過去編集モデルあとから意味を組み替える)）。
- **Accounts**（`Accounts.tsx`・単独画面のほか「補正・勘定科目」内に `embedded` で統合）: 勘定科目を区分ごとに
  残高つきで管理（役割 `role` も表示）。追加 / 編集 / アーカイブ / 削除（参照中は不可）。シートで `type` と `role`
  を選ぶ（`type` 変更時は `role` を既定へリセット、`type` と矛盾する `role` は保存不可）。**内部・聖域化の役割
  （継続コスト台帳=`continuing-cost-asset`）はユーザー編集対象でないため一覧・
  ロール選択肢に出さない**（`isInternalRole`。BS / 資産の内訳には残高として現れる）。**使用中の科目は区分(type)を
  変更不可**（UI で無効化、`upsertAccount` でも fail-closed）。**`role` は使用中でも変更可**。「使用中」判定は
  仕訳/予定CF/継続コストの参照を含む。embedded 時は各 BS 科目行に**「補正」ボタン**（`accounts.adjust`）を出す。
  - **「自由に動かせる」チェック**（`accounts.movable`・現預金の内訳のみ・既定 ON）: OFF にすると
    資金繰りの原資「自由に動かせるお金」に数えない（Suica・チャージ残高など）。BS / 資産の内訳の
    表示は変わらない（「自由に動かせないやつ」枠に移るだけ）。保存されるのは OFF（`movable: false`）
    だけ（ON は保存境界で `undefined` へ正規化）。一覧では OFF の科目に「自由に動かせない」バッジを出す。
  - 箱見出しは細い左罫線で意味色を示す。資産=青系（自由/不自由は濃淡）・負債=赤系・収入=緑系・
    支出=黄〜オレンジ系・純資産=グレー。面を塗らず、`accountBoxes.ts` のアクセントを
    勘定科目・科目ピッカー・資産/負債内訳で共有する。
  - **アーカイブ = 今日時点の残高 0 が条件**（`accounts.archiveToggle`）。残高が残る資産・負債の
    アーカイブは**ホームの振替と同じシート**（EntrySheet の transfer 再利用・アーカイブ対象側は
    固定・金額既定 = |残高|）を経由し、振替の保存と `archived = true` を 1 トランザクションで行う。
    振替をキャンセルしたらアーカイブもしない。残高 0（や収入/支出/純資産の科目）は今までどおり
    即アーカイブ。過去日の表示ではアーカイブ済み科目もその日の残高で出し続ける。
- **補正・勘定科目**（`Adjustments.tsx`、画面名 `manage.title`、**ハンバーガーメニューに昇格**）: 勘定科目管理 +
  初期残高 + 残高補正を 1 画面に統合（設定の「管理」から単独『勘定科目』項目は廃止）。
  - **勘定科目**（上部・`<Accounts embedded>`）: 一覧・追加・編集・アーカイブ/削除。各 BS 科目行の「補正」から
    その科目を選択済みの**残高補正ダイアログ**（`adjustments.createDialog`）を開く（独立フォームは廃止）。
  - **初期残高**（`OpeningSection`）: 新規 BS 科目の作成 + 初期残高付与、または既存科目への付与（`kind='opening'`）。
    一覧から**編集・削除**できる（[初期残高](ledger-concept.md#初期残高)）。
  - **残高補正**（下部）: 登録済み補正の一覧。各行から**編集・削除**（[現実アンカー](ledger-concept.md#残高補正締めなし現実アンカー)）。
    編集時の理論残高は**その補正自身を除いて**計算し直す（二重掛け回避）。差額 0 は削除扱い。削除は確認必須。
    補正仕訳は Journal では読み取り専用（この画面でだけ管理）。
- **Cashflow（資金繰り）**: **確認専用の画面**（独立した入力フォームは持たない）。責務は
  **「現金が枯渇しないか」と「負債返済」を見る**こと。主役は上から ①**「自由に動かせるお金」1 値と
  その推移**（現在/最低額・枯渇警告・表示終了日 `cashflow.until`。原資 = `movable !== false` の
  現預金合計 `freeAssetTotal`。総資金/自由資金の 2 段は持たない）→
  ②**負債・返済**（カード・ローン（`payment/other-liability`）ごとに残高 + 返済予定の次回支払日/残回数/残額。
  **残高があるのに予定が無い負債は「返済予定が未登録」と注意表示**。行タップで返済シート。
  **行の展開（`cashflow.repayments.toggle`）で登録済みの返済（未来日付の保存される仕訳）が並び、
  タップでそのまま仕訳の編集シートを開く**（`cashflow.repayments.row`。紐づけは
  「借方 = その負債・未来日付」で引く）→ ③**未来の入出金・振替予定**（読み取り）→
  ④レガシー予定 CF（残存時のみ表示・実績化/削除のみ）。
  - **入力はホームに一本化**: CF 画面に 収入/支出/振替 ボタンや予定の独立追加 UI は置かない。
    ホームの 収入/支出/振替 で**未来日付**を選んだ通常仕訳が CF に反映される（`cashDeltaOfEntry` で流動資産の
    純増減を求め、`projectCashflow` の `futureEvents` として投影に積む）。二重計上にしない: 未来仕訳は
    `today` 時点の `startTotal` に未含・予定 CF は `status==='planned'`（未実績）で互いに素。
  - **返済は未来日付の保存される仕訳 N 本**（`buildRepaymentEntries` / `createRepaymentEntries`。
    資金繰り画面にも独立の入口がある）。金額・回数が最初から確定しているのでルールにしない。
  - **`CashflowSchedule`（予定CF）はデータとして維持**するが、**新規生成は無い**（既存データの
    一覧 + 実績化 + 削除のみ）。`projectCashflow` は `transfer` では総資金・自由資金を増減させない。
    長期ローン専用スキーマは作らない。
- **Settings**: 先頭に **「管理」セクション**（タグ への遷移。
  勘定科目・残高補正は「補正・勘定科目」へ統合しメニューに昇格したため、ここには出さない。
  各内訳ページはホームの各項目から辿るため含めない）。
  続いて JSON export / import、スナップショット、台帳設定（台帳名・通貨）、アプリ情報、全データ削除。
- **Help**: 使い方の説明（モーダル）。

## ヘッダー（`src/App.tsx` 内）

- 左: ホームアイコン（→ Dashboard）
- 中央: **表示日のチップ**（`UI.period.dateTrigger`）。チップに**透明な `<input type="date">` を
  重ねてあり、1 タップで OS のカレンダーが直接開く**（`UI.period.dateInput`。ポップアップの
  ピッカーは経由しない）。台帳名はヘッダーに出さない。
- 右: `≡`（メニュー）

入力は **ホームの 3 ボタンに集約**し、ヘッダーに `+` は置かない。

### 表示日（1 タップ選択）

表示日は「DB からの抽出条件」＝**日付を 1 つ選んでその断面を見る**（既定 = 起動時の当日）。
`max = 2100-12-31`（`CONTINUOUS_COST_HARD_CAP`）を付け、エンジンが展開できる範囲の外を
そもそも選べなくする（仕訳一覧の from/to も同じ `max`。**入力欄の日付には付けない** —
過去の持ち込みも未来の終了日も自由に入れる）。ヘッダーを年・全期間へ切り替える
`PeriodYearPicker` 等は公開しない。年次の俯瞰は独立した「年間・全体」で行う。

表示日は `App` の共有 state（`ReportPeriod`）でホーム / 各内訳ページ / 仕訳に伝播する
（画面ごとに分岐しない）。

## メニュー（`src/ui/Menu.tsx`）

**中央モーダル / モバイルは下部シート**（共通 `Modal` の dialog variant。右ドロワー `.drawer` は廃止）。
背景タップ・Escape で閉じ、メニュー内クリックでは閉じない。独立した俯瞰画面と管理・補助機能を置く:
**年間・全体 / 毎月のもの / 資金繰り / 補正・勘定科目 / 設定 / ヘルプ**。ホーム=ヘッダーのホームアイコン、
仕訳=ホーム下部「期間内の仕訳」やドリルダウン、各内訳ページ=ホームの各項目から辿る（メニューには置かない）。
勘定科目・残高補正・初期残高は**「補正・勘定科目」に統合**（メニュー）。タグは**設定の「管理」セクション**。

## モーダル / シート規約（`src/ui/Modal.tsx`）

- 閉じ方は **`dismissMode`** で統一する（旧 `dismissable` は後方互換: `false`=`never` 相当）:
  - **`always`**: メニュー / ヘルプ / 軽い選択。背景タップ・`Escape` で閉じる（選んだら閉じる）。
  - **`if-clean`**: 入力フォーム。未編集なら閉じ、**編集済み（dirty）は破棄確認**を出す
    （`useDirtyGuard`。「入力を破棄しますか？」→ 破棄する / 編集を続ける。確認自体は `never`）。
    dirty 判定は各シートで入力フィールドのスナップショットを初期値と比較する。`×` / 背景タップ /
    `Escape` / フッターのキャンセルはすべて `requestClose` を通す。
  - **`never`**: 削除 / 全削除 / import / 復元など破壊的操作。背景タップ・`Escape` で**閉じない**。
- 背景タップ判定は **`onPointerDown` かつ `e.target === e.currentTarget`**（内部要素のタップでは閉じない）。
- 保存 / キャンセルがあるフォームは下部に明確なボタン。フォーカストラップ + 復帰、`role="dialog"` /
  `aria-modal`。

## toast（`src/ui/toast.tsx`）

- 成功 = success（teal）、失敗 = error（赤）。アイコン + 文言。`role="status"` / `aria-live="polite"`。
- **保存失敗時に成功 toast を出さない**（store の各アクションは失敗時 error toast + 例外送出）。

## 危険操作（`src/ui/ConfirmDialog.tsx`）

- 削除 / import 上書き / 復元は確認ダイアログ。確定ボタンは danger 色 + ⚠。
- 全データ削除は **キーワード入力一致**（「削除」と入力）まで確定を無効化。

## 復旧面（`src/ui/ErrorBoundary.tsx`）

ルート直下の ErrorBoundary が描画例外を受け、最小の復旧面を出す: 設定（JSON import への到達）と
**「DB を初期化して再起動」**（`app.recovery.wipe` = `deleteDatabase` → reload。VersionError で
起動できない詰みへの最終手段・確認ダイアログ付き）。「アプリ内の説明文を増やさない」ルールは
通常画面の話で、致命状態の復旧 UI は対象外。

## アクセシビリティ

- 主要操作は `getByRole` / `getByLabelText` で辿れるよう、ラベルと control を id で結ぶ。
- フォーム入力は 16px 以上（iOS のズーム回避）。
- コントラストは WCAG AA を満たす（teal-700 を白文字ボタン背景に使用）。
- スキップリンク、`:focus-visible` のフォーカスリング。
- E2E で axe-core の critical/serious 違反ゼロを検証（`e2e/a11y.spec.ts`）。
